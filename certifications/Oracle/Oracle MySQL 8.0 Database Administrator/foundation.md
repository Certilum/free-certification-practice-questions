### **Backup and Recovery**

### 1. When restoring a very large MySQL dataset, which backup type is generally faster?

- [ ] **A)** Logical backup generated by mysqldump
- [ ] **B)** Physical backup of raw database files
- [ ] **C)** CSV export generated by SELECT INTO OUTFILE
- [ ] **D)** All backup types restore equally quickly

<details>
<summary> 🔍 Reveal Answer</summary>
   
#### **✅ Correct Answer: B**
 
> 💡  **Explanation** 
> 
> Physical backups copy data files directly and avoid parsing and executing SQL statements, so they generally restore faster than logical backups on large datasets.
 
 
</details>

### 2. Which statements about mysqldump --single-transaction are true?

- [ ] **A)** It provides a consistent snapshot for InnoDB tables.
- [ ] **B)** It prevents all writes for the entire backup.
- [ ] **C)** It holds a global read lock until the dump completes.
- [ ] **D)** It allows concurrent DML operations on InnoDB tables.

<details>
<summary> 🔍 Reveal Answer</summary>
   
#### **✅ Correct Answer: A, D**
 
> 💡  **Explanation** 
> 
> The --single-transaction option uses a consistent InnoDB snapshot and does not act as a global lock. It allows DML to continue during the logical backup.
 
 
</details>

### 4. What must exist in addition to a logical backup to restore a database to a specific moment in time?

- [ ] **A)** Binary logs covering the period from the backup time to the target time
- [ ] **B)** Redo logs from before the backup was taken
- [ ] **C)** A copy of the doublewrite buffer

</details>

### 5. Which statements correctly show the difference between redo logs and binary logs?

### 6. Which statement is generally true when comparing logical and physical backups for large MySQL databases?

- [ ] **A)** Physical backups are faster for large datasets.
- [ ] **B)** Logical backups are faster for large datasets.

### **Replication and High Availability**

### 20. For large MySQL datasets, which statement correctly compares logical and physical backups?

- [ ] **A)** Logical backups are faster
- [ ] **B)** Physical backups are generally faster
- [ ] **C)** Both have equal performance
- [ ] **D)** Physical backups are always slower

<details>
<summary> 🔍 Reveal Answer</summary>
   
#### **✅ Correct Answer: B**
 
> 💡  **Explanation** 
> 
> Logical backups rebuild data with SQL operations and add overhead. Physical backups copy raw data files directly, so they are usually faster on large datasets.
 
 
</details>

### 21. Which statements accurately describe the purpose of MySQL binary logs?

- [ ] **A)** Store changes for replication
- [ ] **B)** Enable point-in-time recovery
- [ ] **C)** Handle crash recovery
- [ ] **D)** Replace full backups

<details>
<summary> 🔍 Reveal Answer</summary>
   
#### **✅ Correct Answer: A, B**
 
> 💡  **Explanation** 
> 
> Binary logs record transactional changes and are used for replication and point-in-time recovery. Crash recovery is performed by InnoDB redo logs, and binary logs cannot replace a full backup.
 
 
</details>

- [ ] **B)** It gives a consistent snapshot without a global lock

<details>
<summary> 🔍 Reveal Answer</summary>
   
#### **✅ Correct Answer: B**
 
> 💡  **Explanation** 
> 
> --single-transaction starts a consistent InnoDB transaction or snapshot. It does not stop writes with a global lock, but it still provides a consistent view for InnoDB tables.
 
 
</details>
